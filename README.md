# BT Monitor

Continuous website health monitor for **Banca Transilvania**
(`https://www.bancatransilvania.ro`).

Detects, on every run, on every page of the public site:

| # | Check                       | What it catches                                            |
|---|-----------------------------|------------------------------------------------------------|
| 1 | **Broken links**            | 404s, redirect loops, dead external links                  |
| 2 | **Slow pages**              | TTFB / FCP / load time over a configurable threshold (3 s) |
| 3 | **Missing assets**          | Images, fonts, scripts or stylesheets that fail to load    |
| 4 | **Form issues**             | Broken `action` URLs, no submit button, missing labels     |
| 5 | **Internal-doc leaks**      | PDFs / DOCX containing "Uz intern" / "Confidențial"         |
| 6 | **Visual / "any other"**    | (Optional) Claude vision pass on a sample of pages         |

A FastAPI dashboard renders every report with a health score and one-click
re-runs. A test fixture with **intentional issues** ships with the project
so reviewers can verify that every check actually detects what it claims to.

## Architecture

```
              ┌──────────────────────────────────────┐
              │   runner.py — single entry point      │
              └────────┬─────────────────────────────┘
                       │
        ┌──────────────┼──────────────┬────────────┬────────────┐
        ▼              ▼              ▼            ▼            ▼
   crawler/      checks/links   checks/perf   checks/assets   checks/forms
   sitemap.py    .py            .py            .py             .py
                                  │
                                  ▼
                             checks/docs.py
                                  │
                                  ▼
                       data/*.json   ◄────── dashboard/ (FastAPI)
```

**One config switch** — the target site is set via the `BT_MONITOR_BASE_URL`
environment variable. Every module reads it from `config.py`. Swap one value,
and the whole tool retargets.

## Requirements

- Windows / Linux / macOS
- **Python 3.11+** (developed on 3.13)
- ~250 MB free disk (Playwright Chromium download)
- Outbound HTTPS to the target site

## Install

```bat
:: 1. Clone the repo
git clone <repo-url> bt-monitor
cd bt-monitor

:: 2. Create a virtual env
py -3.13 -m venv .venv

:: 3. Install Python deps
.venv\Scripts\python.exe -m pip install -r requirements.txt

:: 4. Download the browser Playwright drives
.venv\Scripts\python.exe -m patchright install chromium
```

(On Linux/macOS replace `.venv\Scripts\python.exe` with `.venv/bin/python` and `py -3.13` with `python3.13`.)

> **Note for new contributors:** the `data/` folder is empty in git — every JSON in there
> is generated by a scan. After install, run `python runner.py` (or click "Run all checks"
> in the dashboard) to populate it.

## Usage

### Run a one-shot scan from the command line

```bat
.venv\Scripts\python.exe runner.py
```

Each step prints its own summary and saves a JSON report under `data/`.
A consolidated `data/summary.json` is written at the end.

### Run the dashboard (recommended)

```bat
.venv\Scripts\python.exe -m uvicorn dashboard.app:app --host 127.0.0.1 --port 8000
```

Open <http://127.0.0.1:8000>. Click **Run all checks**; the page polls
`/api/state` and refreshes automatically when the run finishes.

### Targeting

```bat
:: Default — the user's own agency site (no WAF, full access)
set BT_MONITOR_BASE_URL=https://www.resetmedia.ro

:: Local test fixture (every issue type intentionally present)
set BT_MONITOR_BASE_URL=http://127.0.0.1:8765
.venv\Scripts\python.exe test_fixture\server.py    & rem run in another shell

:: Production target (requires Akamai allowlist — see Deployment section)
set BT_MONITOR_BASE_URL=https://www.bancatransilvania.ro
```

Then run `runner.py` or the dashboard as above.

## Test fixture — proving every check works

`test_fixture/server.py` is a small Flask app that serves 8 pages, each
broken in a specific way:

| URL                            | Intentional issue                                 |
|--------------------------------|---------------------------------------------------|
| `/`                            | Healthy homepage                                  |
| `/clean-page`                  | Healthy (sanity baseline)                         |
| `/broken-links`                | 4 dead anchors + a redirect loop                  |
| `/missing-assets`              | Missing image + missing font                      |
| `/slow`                        | 5-second server-side delay                        |
| `/broken-form`                 | Form posts to `/this-endpoint-does-not-exist`     |
| `/good-form`                   | Well-formed form (control)                        |
| `/docs` + `/static/uz-intern.pdf` | PDF containing "Uz intern" + "Confidențial"   |

Start it, point the tool at it, and confirm every issue is reported:

```bat
.venv\Scripts\python.exe test_fixture\server.py
:: in another shell:
set BT_MONITOR_BASE_URL=http://127.0.0.1:8765
.venv\Scripts\python.exe runner.py
```

Expected: 5 broken links · 1 slow page · 3 asset failures · 1 form with
3 issues · 1 internal-doc leak.

## Deployment to Banca Transilvania production

`bancatransilvania.ro` is protected by **Akamai Bot Manager** (verified
2026-05-12, error reference `errors.edgesuite.net`). Akamai inspects
TLS / HTTP/2 fingerprints and injects sensor-data challenges. **The tool
will not function against the real site without explicit allowance from
the BT infrastructure team.** This is intentional, by design, and the
correct thing for a bank to have in place.

Three viable paths — pick whichever BT's infosec team prefers:

1. **Allowlist a dedicated User-Agent in Akamai.** We adopt a clear identifier
   such as `BT-Monitor/1.0 (contact: <your-team-email>)`. BT adds a Bot
   Manager rule that allows this UA. No bypass tricks, fully audit-able.

2. **Run from inside BT's network.** Akamai exempts BT's own egress IPs
   from Bot Manager. We deploy the tool on a small VM / container in BT's
   infra and run on a cron. Reports are pushed to a Teams webhook.

3. **Provide a staging URL.** A pre-prod or canary environment without
   the production WAF is by far the easiest path for the form-submission
   check (which needs to actually post real test leads).

For the form-submission test specifically (the brief's
"lead-ul se trimite catre noi"), we **need** path 3 or a designated test
lead convention (e.g. all leads with `email = "monitor-test@bt-monitor.local"`
are filtered out of the CRM at intake).

When BT grants any of the above:

```bat
set BT_MONITOR_BASE_URL=https://www.bancatransilvania.ro
.venv\Scripts\python.exe runner.py
```

Nothing else changes.

## Configuration

`config.py` defines:

| Setting                  | Default       | Purpose                                |
|--------------------------|---------------|----------------------------------------|
| `BASE_URL`               | env override  | Target site                            |
| `USER_AGENT`             | Chrome 126    | Identifies us to remote servers        |
| `CRAWL_TIMEOUT_MS`       | 30 000        | Per-page navigation timeout            |
| `SLOW_PAGE_THRESHOLD_MS` | 3 000         | "Slow" boundary used for the perf flag |
| `DATA_DIR`               | `data`        | Where reports are written              |

Set `BT_MONITOR_BASE_URL` in the environment to override `BASE_URL` without
editing the file.

## Scheduling continuous runs

On Windows, use Task Scheduler:

```
Action:    .venv\Scripts\python.exe
Argument:  runner.py
Start in:  C:\path\to\bt-monitor
Trigger:   every 6 hours
```

On Linux, a cron entry:

```cron
0 */6 * * * cd /opt/bt-monitor && /opt/bt-monitor/.venv/bin/python runner.py >> /var/log/bt-monitor.log 2>&1
```

For "continuous" the brief asks for: every 6h is the sensible default.
Anything sub-hourly risks looking like a stress-test to Akamai.

## Why this stack

- **Patchright + Playwright Chromium** — modern bank sites are React/SPA;
  a real browser is the only reliable way to see what users actually see.
  Patchright's headless evasion isn't needed against `resetmedia.ro` but
  keeps options open for sites with light bot protection.
- **httpx** — for fast parallel link probes (10× faster than Playwright
  for plain HEAD/GET checks where rendering is not needed).
- **pypdf + python-docx** — pure-Python doc text extraction, no external
  dependencies, works offline.
- **FastAPI** — minimal, async-native, ships with auto-docs at `/docs`
  if you need to wire alerts in later.
- **Flask** (test fixture only) — simplest way to spin up a deterministic
  broken site for self-tests.

---

## What this tool deliberately does NOT do

- **It does not submit real forms.** End-to-end submission against
  production would create real leads in BT's CRM. The brief's
  "lead-ul ajunge la noi" check requires a staging environment or a test-
  lead convention. The static analyzer reports everything it safely can
  (action URL reachable, fields present, labels, submit button, etc.) and
  flags `submission_test = "not_run"` in the JSON so reviewers know it's
  intentional, not missing.
- **It does not try to bypass Akamai.** See the Deployment section.
- **It does not store screenshots by default.** Add `--save-screenshots`
  to `runner.py` when the AI visual pass is enabled.

## Collaborating

Two-person workflow:

```bat
:: pull latest changes before you start work
git pull

:: do your changes, then
git add <files-you-touched>
git commit -m "what you changed and why"
git push
```

**Branch convention (optional but recommended once you're more than 1):**

```bat
:: feature work goes on a branch, never directly on main
git checkout -b feature/teams-webhook
:: ...code...
git push -u origin feature/teams-webhook
:: open a Pull Request on GitHub, get a quick review, merge
```

**What's safe to commit:**
- Anything under `crawler/`, `checks/`, `dashboard/`, `test_fixture/`, plus the top-level
  `config.py`, `runner.py`, `requirements.txt`, `README.md`.

**What is NOT committed (and shouldn't be):**
- `data/*` — every JSON / log there is per-run output. Yours and your colleague's
  scans don't need to overwrite each other.
- `.venv/` — each person creates their own.
- `.env` — secrets like `ANTHROPIC_API_KEY`. Share via 1Password / Bitwarden, never git.
